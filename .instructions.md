# DevOS Development Guide

## Code Standards

### ✅ Do's
- **30 lines max per file** — Split into multiple files if larger
- **Single comment line** for each code block explaining purpose
- **Modular functions** — One responsibility per function
- **Type hints** — Use Python type hints, TypeScript for JS
- **Async/await** — All I/O operations are non-blocking
- **Error handling** — Try-catch with specific error messages
- **Env variables** — Use .env for secrets, never hardcode

### ❌ Don'ts
- No monolithic files or classes
- No commented-out code — delete or document
- No console.log in production code
- No hardcoded API keys or URLs
- No mixing concerns (UI + logic, DB + API)

## Folder Structure Rules

```
[domain]/
├── types.ts           # TypeScript interfaces/types
├── constants.ts       # Enums, defaults, static data
├── [feature].ts       # One feature per file (max 30 lines)
└── index.ts           # Exports for the domain
```

## Function Rules

- **Pure functions first** — No side effects
- **Single parameter objects** — For > 2 params
- **Return types explicit** — Always specify return type
- **Naming:** camelCase for functions, UPPER_CASE for constants

## File Naming

- Components: `PascalCase.tsx` (e.g., `DailyCard.tsx`)
- Hooks: `useCamelCase.ts` (e.g., `useAgentStatus.ts`)
- Utils: `camelCase.ts` (e.g., `formatDate.ts`)
- Types: `types.ts` or `[domain].types.ts`
- Constants: `constants.ts`

## Comments Rule

**Exactly one comment per function/block explaining its purpose:**

## Testing

- Unit tests in `[feature].test.ts` (same folder)
- Mock data in `mocks.ts`
- Run `npm test` or `pytest -v`

## Git Workflow

```bash
git checkout -b feat/module-name
# Make changes following above rules
git commit -m "feat: add [module] - brief description"
git push origin feat/module-name
```

## API Standards

- REST endpoints: `/api/v1/resource`
- Request body: `{ data: {...} }`
- Response: `{ success: boolean, data: T, error?: string }`
- Errors: Use HTTP status codes (400, 401, 404, 500)

## Agent Standards (LangGraph)

- State: Define in `types.ts`
- Nodes: One per `[agent].ts` (max 30 lines)
- Tools: One per file in `tools/`
- Orchestration: In `graph.ts`
